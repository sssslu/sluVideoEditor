## 1.10 소스 검증과 인물 배경 제거

CPU/DirectML RVM 모델, 프레임 간 상태 유지, GPU 오류 시 CPU 전환, 별도 작업 프로세스의 취소·종료를 구현했습니다. GPU 경로는 원본 가중치를 유지하면서 픽셀 입력·출력 변환을 GPU에서 처리합니다. 255개 양자화 경계와 인접 Float32 값, 모든 입력 바이트의 정규화가 독립 기준과 일치하며 GPU 실행도 확인했습니다.

속성의 인물 배경 제거에서 구도와 처리 장치를 선택하고 적용·해제할 수 있습니다. 타임라인 효과·속도와 이전 원본 처리 정보를 보존하고 실행 취소를 지원합니다. 원본 연결은 프로젝트 형식 9에 저장합니다. 투명 FFV1 영상은 일반 프록시 설정이 꺼져 있어도 투명 WebM으로 재생하며, 모아 저장한 프로젝트를 다시 열면 필요한 프록시를 재생성합니다. 처리 중 원본 구간이 바뀌면 결과가 기존 편집을 덮어쓰지 않습니다.

배경 제거 결과의 역재생은 FFV1으로 색상·투명도를 보존합니다. 가변 프레임 시각과 여러 처리 구간의 경계를 포함한 실제 픽셀 검사에 통과했습니다. 개발 소스에는 투명 영상의 흔들림 보정도 연결했습니다. 색상과 투명도에 동일한 보정 경로를 적용하고 투명 영역의 숨은 색이 테두리에 섞이지 않도록 처리합니다. FFV1·투명 WebM, 회전·비정사각 픽셀, 가변 프레임 시각, 구간 끝 길이, 지연 영상과 AAC 샘플 보존을 검사했습니다. 흔들림 보정 계산은 CPU입니다. HDR·고비트 입력은 지원하지 않습니다. 분할·트리밍 및 이전/이후 처리 조합 36가지는 원본 구간 복원 데이터 검사이며, 모든 조합의 영상 처리가 검증됐다는 뜻은 아닙니다.

실제 작업 프로세스 검사 12개에는 CPU/GPU 각각 720p 인물 60프레임, 4K 원본 1초의 실제 31프레임·투명 프록시·합성 출력, 취소·강제 종료·손상 모델 처리가 포함됩니다. 한 실행에서 종료된 작업 PID의 즉시 소멸 확인이 실패했으며 원인은 확정하지 않았습니다. PID를 포함한 종료 기록을 추가한 전체 재검사와 별도 정상 종료/시작 중 취소/프레임 중 취소 24회는 통과했습니다.

ResNet50의 CPU/DirectML 연속 처리, 상태 초기화, 같은 상태를 사용한 CPU 재시도, 720p·4K 실제 배경 제거 경로, 영상 표시 시각·마지막 프레임 길이·지연 스테레오 PCM 보존, 취소와 작업 프로세스 종료를 포함한 네이티브 검사 **9개**가 통과했습니다. ONNX Runtime 프로파일에서 원본 모델의 합성곱 연산이 DirectML에서 실행됨을 확인했습니다. 검사 코드·모델·실행 바이너리·입력·출력 해시를 함께 보관합니다. 기록은 `.test-artifacts/matting-precision/run-afAmw6`에 있습니다.

선택 구간 앞뒤의 실제 프레임을 확인해 범위가 입증되면 전체 원본 시각 분석을 생략하도록 보완했습니다. 캐시가 없는 4K 59.6초 구간 표본에서는 두 번의 구간 탐색으로 68개 프레임 기록을 받아 경계를 확인했습니다. 희소 VFR, 지연 영상, 양수 시작 시각, 파일 끝의 실제 길이, 디코더 오류·취소·원본 변경을 검사했습니다. 선택 구간에 오디오 샘플이 없는 트랙도 채널·샘플률·트랙 순서를 유지합니다.

배경 제거 입력은 표시 크기 최대 4096픽셀의 SDR 인물 영상입니다. HDR, 기존 투명 영상의 추가 배경 제거, 일반 사물 분리·브러시 보완은 지원 범위에 포함되지 않습니다. 다양한 촬영 장면과 긴 실제 편집 작업의 품질 검증을 계속해야 합니다.

### 검사 실행과 추가 기능 검토

사용자 작업 중 검사 창이 나타난 뒤 자동 검사 실행 경로를 수정했습니다. 현재 GUI 검사는 별도의 Windows 데스크톱에서 실행하고, 소유 프로세스와 하위 프로세스를 작업 개체에 묶어 종료합니다. 일반 종료·표준 입력 종료·부모 프로세스 종료·강제 종료에서 정리를 확인했으며 실제 Electron 검사도 이 경로로 통과했습니다. 사용자가 보는 입력 데스크톱은 전환하지 않습니다. 이 구성은 검사 도구에 적용합니다.

객체 추적의 영역 지정·검토·수정·자막/이미지 연결·미리보기·출력, 프로젝트 모아 저장, 누락된 추적 파일 다시 연결을 구현했습니다. 1.9 설치형·포터블 EXE를 생성하고 실제 배포 앱에서 검증했습니다.

이번 변경 후 전체 소스 검사는 329개 중 324개 통과·선택형 5개 제외·실패 0개이며 빌드와 통합 검사도 통과했습니다. 기존 화면 24개 묶음의 286개 항목, 추적 관련 7개 묶음의 53개 항목, 별도 출력 부하·CPU/GPU 역재생·자막 출력·한글/영어 음성 인식 검사가 통과했습니다. 실제 소스·모델 해시를 대조한 `.test-artifacts/verification-1.9.0.json`을 남겼습니다. 최초 스코프 제한 시간 초과와 숨김 설정 재검사 내역은 검증 기록과 원본 로그에 명시했습니다.

실제 배포 EXE에서도 24개 기존 화면 검사 286항목과 추적 7개 검사 53항목, 별도 GPU 전환·자막·오디오 출력 24항목이 통과했습니다. CPU와 DirectML 분석, 4K 영상 처리 중 편집·저장·취소, 모아 저장·파일 이동·추적 파일 복구를 포함합니다. 모델·작업 코드와 네 개의 네이티브 추론 바이너리까지 설치 내부 파일을 대조한 235개 검사와 포터블 실행 8개 검사가 통과했습니다. 일반 실행 인수의 포터블 내부 파일 154개는 검증한 실행 폴더와 같으며 설치형 전용 `resources/elevate.exe`만 비교에서 제외합니다. 이 PC의 새 프로필에서 편집 화면까지 5.603초였으며 환경별 시작 속도는 보장하지 않습니다. Windows 코드 서명, 실제 대화형 설치와 다른 PC의 호환성은 검증 범위에 포함되지 않습니다.

누락되거나 손상된 추적 결과는 연결된 자막·이미지의 **객체 추적 → 추적 파일 다시 연결**에서 백업을 선택해 복구합니다. 원래 추적 파일의 내용과 분석 당시 영상의 내용을 각각 확인합니다. 추적 파일이 없는 동안 원본을 여러 번 옮기고 저장해도 분석 당시 영상 확인 정보는 보존합니다. 같은 이름이나 같은 머리글의 변조 파일은 복구 대상으로 인정하지 않습니다. 복구 도중 연결을 해제하거나 다른 프로젝트를 열면 늦게 도착한 결과를 적용하지 않으며 복구는 한 번에 실행 취소할 수 있습니다. 실제 화면의 취소·복구·저장·재열기·GPU/CPU 미리보기와 120프레임 출력, 원본 없는 상태의 복구와 원본 변경·취소 시 임시 파일 정리를 검사했습니다. 재현: `node scripts/e2e-tracking-reconnect.mjs`, `npx tsx --test tests/project-assets.test.ts`.

4K 추적의 반복 디코딩을 줄였습니다. 큰 분석 프레임의 역방향 처리는 기본 256MiB 이내 임시 파일을 재사용하며, 전체 영상을 메모리나 임시 파일에 펼치지 않습니다. 이 PC의 4K30 20초 구간을 1280픽셀 분석/DirectML로 처리한 표본은 메모리 버퍼 방식 65.24초에서 임시 파일 방식 29.25–29.41초로 줄었고, 두 방식의 600개 추적 기록은 같았습니다. 4K30/60의 6개 구간과 1분 연속 분석, 실제 화면의 처리 중 편집·저장·취소를 검사했습니다. 영상은 공개 저해상도 표본을 확대·반복한 부하 검사 자료이므로 원래 4K 촬영 영상의 정확도나 일반 처리 속도를 뜻하지 않습니다. 디코딩은 CPU이며 모델 추론은 DirectML입니다. 메모리 측정은 해당 작업 프로세스의 사용량으로, VRAM이나 전체 앱 상한이 아닙니다. 재현: `node scripts/benchmark-tracking.mjs`, 빌드 후 `node scripts/e2e-tracking-stress.mjs`.

프레임 탐색이 간헐적으로 빈 결과를 반환해 처음부터 재탐색하던 호출도 수정했습니다. 번들 FFprobe 8.0.1에서 종료 시각을 생략할 때 초기화되지 않는 필드가 이후 사용되는 경로를 피하도록, 지원하는 영상 시각보다 먼 명시적 끝점을 지정합니다. 실제 종료 판단은 디코딩된 표시 시각을 따르므로 B 프레임이나 긴 가변 프레임 간격을 잘라내지 않습니다. 새 프로세스 반복 실행, 정지 화면·CPU/GPU 역재생과 추적, 한 시간 간격의 2프레임 영상으로 검사했습니다. 근거: [번들 버전 FFprobe 소스](https://github.com/FFmpeg/FFmpeg/blob/n8.0.1/fftools/ffprobe.c), `tests/video-frame.test.ts`.

1,084,419,327바이트의 유효한 4K 영상 하나를 공유하는 클립 10,000개 프로젝트도 모아 저장·폴더 이동 후 다시 연결·복사 도중 취소를 검사했습니다. 이 PC의 소스 엔진 측정에서 모아 저장은 2.73초, 이동 후 연결은 0.76초였으며 취소 시 이전 프로젝트와 원본 내용이 보존되고 임시 복사본이 제거됐습니다. OS 파일 캐시가 있는 로컬 파일시스템 표본이며, 외장 드라이브 속도나 클립 10,000개의 화면 재생 성능을 뜻하지 않습니다. 재현: `npx tsx scripts/stress-project-assets.ts`.

개발 소스에 **프로젝트 → 프로젝트 모아 저장**을 추가했습니다. 라이브러리의 영상·음성·이미지와 추적 파일을 프로젝트 옆의 `.slu-data` 폴더로 복사합니다. 이동할 때 `.sluproj`와 이 폴더를 함께 옮겨야 합니다. 일반 저장은 원본 영상을 복사하지 않고 추적 파일을 함께 보관합니다. 복사본에는 파일 내용의 SHA-256과 상대 경로를 기록하며, 같은 원본임이 확인될 때만 새 경로의 추적 연결을 복원합니다. 기존 원본이 남아 있어도 프로젝트 폴더 안의 복사본을 먼저 선택합니다. 프로젝트 파일은 복사·검사가 끝난 뒤 교체하며, 모아 저장은 작업 패널에서 취소할 수 있습니다. 복구 기록과 현재 편집 세션의 경로는 그대로 유지합니다.

소스 앱에서 모아 저장·폴더 이동·다시 저장과 재열기·GPU/CPU 미리보기·실제 출력·취소·일반 저장과의 순서 보존을 검사했습니다. 출력 120프레임 중 독립적으로 확인한 4개 시각의 추적 위치 오차는 2픽셀 미만이었습니다. 서로 다른 파일의 같은 이름, 데이터 변조, 복사 중 원본 변경·취소, 연결된 폴더의 경로 제한, 하드 링크가 없는 파일 시스템의 복사 대체 경로도 검사합니다. 위의 제한된 로컬 부하 표본 외에 다른 PC와 실제 외장 드라이브의 성능은 검증하지 않았습니다. 재현: `npx tsx --test tests/project-assets.test.ts`, 빌드 후 `node scripts/e2e-project-assets.mjs`.

영상 클립의 속성에서 `객체 추적 → 대상 지정`을 열어 상자를 그립니다. 멈춘 화면은 분석과 같은 원본 디코더·색상·시각을 사용하며, 앞뒤 프레임 버튼은 명목 FPS 대신 실제 표시 시각을 따릅니다. GPU/CPU 분석, 중간 기준점에서 앞뒤 추적, 추가 기준점과 재분석, 새 텍스트 또는 기존 이미지·자막 연결, 크기 따라가기, 연결 해제와 실행 취소를 지원합니다. 검토 화면에서 재생을 멈추거나 탐색하면 요청한 프레임이 준비된 뒤에만 지정·적용할 수 있습니다. 현재 위치에서 연결을 해제하거나 재분석을 적용해도 자막 위치가 튀지 않도록 기존 변환을 보존합니다.

실제 소스 앱의 추적 작성 검사 11개를 통과했습니다. DirectML 100프레임 분석, 영역 수정, 원본 분할 뒤 재분석, 저장·재열기, 취소 및 늦은 완료 무시, 이미지 연결, 희소 VFR의 0→2→4초 프레임 이동, 1100×720 화면의 조작 가능 여부를 검사했습니다. UI로 만든 한글 자막의 100프레임 출력 중 4개 표본에서 미리보기와 흰 글자 중심 차이는 2픽셀 미만입니다. 이는 모델 추적 정확도 수치가 아닙니다. 재현: 빌드 후 `node scripts/e2e-tracking-authoring.mjs`. 프로젝트 이동·복구와 4K 부하 검사는 위에 별도로 기록했습니다.

원본을 분할하면 연결된 자막·이미지는 분할된 원본 조각들을 함께 참조합니다. 조각별 위치·크롭·속도 변경을 따르며, 빈 구간에서는 가장 최근에 끝난 조각의 마지막 포함 프레임을 유지합니다. 겹치는 구간은 시작 시각이 늦은 조각을 우선하고, 같은 시작 시각이면 뒤쪽 분할 조각을 우선합니다. 삭제된 조각은 마지막 설정을 보존하며 실행 취소하면 실제 클립 연결을 복원합니다. 잠긴 자막의 길이·위치·키프레임을 임의로 나누지 않습니다. 원본 조각과 자막을 함께 복사하면 새 원본 조각들에 연결됩니다. 연결당 최대 10,000개 조각, 프로젝트 전체 최대 50,000개 원본 참조를 검증하며, 재생 중 매 프레임 전체 클립을 검색하지 않습니다. 실제 앱 분할 검사 6개와 기존 연결 검사 7개를 통과했습니다. 속도 곡선·크롭·회전·크기 변화가 있는 영상의 비정수 시각 2회 분할 전후 240프레임 출력이 픽셀 단위로 같았으며, 수정된 오른쪽 조각을 삭제해 보존한 결과도 120프레임 출력이 같았습니다. 재현: `npx tsx --test tests/motion-split.test.ts tests/motion-render.test.ts`, 빌드 후 `node scripts/e2e-motion-split.mjs`.

추적은 사용자의 위치·크기·키프레임에 추가되며, 원본의 크롭·화면 맞춤·반전·회전·속도 곡선을 반영합니다. 원본 클립을 삭제하면 마지막 원본 설정을 남기고, 실행 취소하면 연결을 복원합니다. 복사·붙여넣기와 캔버스 크기 변경도 연결 정보를 유지합니다. 경로는 별도 `.slutrack` 파일이며 프로젝트에 프레임 전체를 펼쳐 넣지 않습니다. 미리보기는 최대 64개×512프레임 페이지를 보관하고 출력은 최대 6초 구간마다 필요한 프레임만 계산합니다. 120fps 출력 480프레임의 위치, 비정수 컷·크기 변화·회전·전환을 포함한 서로 다른 구간 길이의 출력 일치, 실제 앱의 저장·재열기·GPU/CPU 미리보기·드래그·삭제/실행 취소·복사/붙여넣기·자막 출력을 검사합니다. 이 별도 검사는 미리 작성한 연결을 사용하며, 위의 작성 UI 검사와 구분합니다. 재현: `npx tsx --test tests/motion.test.ts tests/motion-render.test.ts`, 빌드 후 `node scripts/e2e-motion-binding.mjs`.

실제 파일의 프레임과 시각을 같은 디코더에서 읽으며, 중간 시점의 기준점에서 앞·뒤로 추적합니다. 뒤쪽 기준점을 처리한 뒤에도 역방향에는 첫 기준점을 다시 사용합니다. 결과는 프레임당 32바이트의 별도 파일로 저장하고 필요한 구간만 읽습니다. 작은 분석 프레임의 역방향 RAM 버퍼는 기본 32MiB이며, 큰 프레임에서는 위의 디스크 버퍼를 사용합니다. RAM 방식에서 프레임 하나가 예산보다 크면 그 한 프레임을 보관합니다. 이는 전체 프로세스 메모리 상한이 아닙니다. 회전·비정사각 픽셀·SDR 색상·투명 VP8/VP9, 취소·원본 변경·작업 프로세스 종료 및 CPU 재시도를 검사했습니다. 실제 Electron 작업 프로세스의 100프레임 영상에서 중간 기준점과 수동 재지정 후 평균 겹침 비율은 CPU/GPU 모두 0.82185였습니다. 이 표본의 수치를 일반 정확도로 확대하지 않습니다. 실제 앱 API에서도 GPU 분석·50개 시각·결과 구간 읽기·잘못된 요청 거부·취소·원본 변경 감지를 확인했습니다. 재현: `npx tsx --test tests/tracking-pipeline.test.ts`, 빌드 후 `node scripts/e2e-tracking-ipc.mjs`.

1.8.0에서는 흔들림 보정에서 컷 시작 시점에 표시 중인 프레임이 빠지는 문제, VP9 전체 범위 색상의 변환 오류, AAC 탐색에 따른 디코딩 샘플 차이와 MOV의 지연 오디오 시각 반올림을 수정했습니다. 소스 앱과 새 EXE의 각각 14개 검사에서 8가지 구간의 프레임·시각·오디오와 6종 영상의 색상을 확인했습니다. 비교한 평면 색상 샘플 차이는 모두 0/255였으며, 이 결과를 임의의 실영상 품질 보장으로 확대하지 않습니다. 보정은 여전히 CPU의 2단계 libvidstab 처리이며 8비트 SDR만 지원합니다.

1.7 배포 EXE의 GPU 전환 7개·자막 출력 5개·오디오 출력 12개, 포터블 8개와 설치 payload 168개 검사를 통과했습니다. 포터블 첫 화면은 이 실행에서 6.81초였고 별도 파일 비교 실행에서는 4.73초였습니다. 압축 해제된 115개 파일이 unpacked 배포와 바이트가 같으며 설치형 전용 `resources/elevate.exe`만 비교에서 제외했습니다. 이 PC의 관찰이며 일반 성능 보장이 아닙니다. 실제 설치 절차와 다른 PC는 검증하지 않았습니다.

1.6에 오디오 레벨 미터와 클립별 6밴드 EQ를 추가했습니다. 소스 앱과 실제 EXE 각각 195개 검사를 통과했습니다. 여기에 배포 EXE의 GPU 전환 출력 7개·자막 출력 5개·오디오 출력 12개, 포터블 8개와 설치 payload 168개 검사를 완료했습니다. 프로젝트 형식 6을 사용하며 형식 1–5를 읽습니다. 이전 EXE는 형식 6 파일을 열 수 없습니다.

EQ는 저역/고역 차단, 저역/고역 선반, 피크 필터·주파수·게인·Q·출력 트림·바이패스·프리셋을 지원합니다. 그래프 드래그, 키보드, 실행 취소, 복사, 저장, 다중 선택과 트랙 잠금을 검사했습니다. 실제 WebAudio와 내보내기 기준 PCM의 8조건 비교에서 최대 차이는 1.49×10⁻⁸이었습니다. 일반/곡선 속도의 구간별 출력과 중간부터 출력은 각각 같은 샘플을 유지했습니다.

추가로 분할 지점에서 EQ 상태가 초기화되는 문제를 재현해 수정했습니다. 같은 원본·EQ·볼륨·페이드가 이어지는 단순 분할은 오디오를 연속 처리하며, 영상 클립과 효과는 독립적으로 유지합니다. 일반/곡선 속도에서 두 번 분할한 144,000개 스테레오 프레임과 부분 출력은 분할 전과 바이트가 같습니다. 실제 영상/오디오 재생도 두 컷을 지나는 동안 같은 디코더·EQ 상태와 일정한 음량을 유지했습니다. 음소거·해제·개별 EQ 수정 후 그룹 해제까지 실제 앱 8개 검사를 통과했습니다. 원본·효과·페이드 변경이나 전환이 있는 경계는 별도 처리합니다. 명시적인 탐색 직후의 필터 준비와 장시간·다중 트랙 부하는 추가 확인 대상입니다.

첫 재생에서 원본 오디오 시각이 프로그램 시계보다 약 0.23–0.32초 늦어지면서 불필요한 보정 탐색을 하던 문제도 확인했습니다. 미디어 준비·재생 시작을 기다리고 실제 오디오 시각으로 프로그램 시계를 진행하도록 수정했습니다. 소리가 없는 구간은 기존 시간 기준을 사용합니다. 현재 빌드·통합 검사, 기본 221개 중 216개 통과·선택형 5개 제외, 실제 소스 앱 195개 검사를 통과했습니다. 추가 출력·픽셀·자막 증거의 소스 해시도 대조했습니다. 미리보기의 원래 미디어 후보 32개에 연속 오디오용 보조 디코더가 최대 32개 추가될 수 있으며, 오디오 전용 클립의 연속 그룹은 오히려 디코더 수를 줄입니다.

배포 EXE에서 6초짜리 원본·EQ·분할·속도 곡선·중간 EQ 변경을 WAV로 출력한 여섯 경우 모두 288,000개 스테레오 프레임을 유지했습니다. 소스 믹서 기준과 최대 차이는 1/65,536으로 16비트 양자화 범위였고, 이 조건의 일반/곡선 속도 분할 전후 WAV 샘플은 바이트가 같았습니다. 곡선 제어점을 재구성한 소스 float PCM에는 최대 7.45×10⁻⁹의 반올림 차이가 있어 모든 조건에서 float 바이트 일치를 주장하지 않습니다. 이 검사는 배포 경로 검증이며, 별도의 FFmpeg·WebAudio 비교가 필터 계산을 검증합니다.

포터블 시작은 같은 1.5 payload로 압축 방식을 비교했습니다. 기존 압축 12.53/12.01초, ZIP 7.27/4.75초였고 추출된 모든 파일의 바이트가 같았습니다. 실험용 EXE 크기는 246 → 351MB로 늘었습니다. 1.6 포터블에 ZIP을 반영한 뒤 첫 화면은 11.27초, 별도 payload 확인 실행은 8.36초였습니다. 추출된 프로그램·런타임·문서 115개 파일이 unpacked 배포와 바이트가 같습니다. electron-builder가 설치형에만 넣는 `resources/elevate.exe`는 비교 제외를 명시했습니다. 캐시·다른 앱 부하가 통제된 일반 성능 보장이 아니며 과거 40.51초 관찰도 보존합니다.

## 1.3 검증 기록

- 디졸브·와이프·밀어내기·줌의 실제 UI 17개, 비동기 전환 작업 6개, GPU/CPU 기준 픽셀 비교 360개를 통과했습니다. 전체 기본 검사 155개 통과·선택형 5개 제외, 실패 0개이며 실제 소스 앱과 배포 EXE에서 각각 118개 흐름을 통과했습니다.
- 실제 영상 시작·끝을 따로 분석해 오디오 길이를 영상 핸들로 오인하지 않습니다. 전환은 원래 클립의 시간 계산을 유지하며 노출 구간만 확장합니다. 공유 중간 클립은 한 디코더로 처리합니다.
- 네 전환의 1초·6초 출력 구간 바이트가 같고, 세 오디오 모드의 샘플·연속 디코더·64점 속도 커브 외부 노출·취소 검사를 통과했습니다. 원본 클립·효과와 전환 밖 프레임은 보존됩니다.
- 1080p 4초 이미지 두 장·마스크·회전·반투명 출력에서 디졸브 5.260초, 와이프 5.442초, 밀어내기 5.857초, 줌 5.854초를 측정했습니다. 초기 디졸브 CPU 식 계산은 46.590초, 밀어내기 CPU는 36.051초였습니다. 밀어내기·줌은 FP64 좌표·16비트 OpenCL GPU, 디졸브·와이프는 최적화된 CPU 혼합을 사용합니다. 인코더는 NVENC이며 합성이 모두 GPU에서 실행된다고 주장하지 않습니다. 단일 표본을 일반 영상 성능으로 일반화하지 않습니다.
- 같은 경로의 원본 교체·프록시 무효화·재연결, 프로젝트/작업 세션, 지연 저장 경로, 실행 취소의 오래된 원본 정보 복구 문제를 수정했습니다. 실제 원본 변경 시 자막·보정·출력 결과 게시를 거부합니다.
- GPU가 이미 프레임을 전달한 뒤 고의로 실패시켜도 전체 CPU 재시도 결과는 CPU 기준 영상·비무음 오디오와 같습니다. 취소 후 디코더·네이티브 오디오·인코더가 남지 않았습니다. 배포 EXE에서도 실제 OpenCL·번들 네이티브 오디오·NVENC와 CPU 전환 선택을 검사했습니다.
- 120fps 비선형 자막 누락을 수정했고 736프레임의 1초·6초 구간이 일치했습니다. ASS의 1/100초 제한 및 Canvas/ASS 표현 차이는 남습니다.
- 포터블 8개 검사를 통과했고 첫 화면은 이 환경에서 11.65초였습니다. 설치 payload 145개 검사와 런타임·문서·고지 해시를 확인했습니다. 설치 프로그램 자체를 실제 설치했다고 주장하지 않습니다. 기존 1.2 실행 파일·버전별 해시 기록은 그대로 보존합니다.
- 자막 단계 설계는 `.work-notes/caption-next.md`에 있으며 아래 1.4 소스 구현으로 이어졌습니다.

## 1.4 검증 기록

- 음성 인식 단어 시간의 측정/수동/추정 출처와 문자열 구간을 보존하고 분할·트림·비선형 속도에 맞춰 변환합니다. 문구 변경 시 연결을 해제하고 실행 취소로 복구합니다. 실제 한국어·영어 CPU 모델 검사는 `scripts/check-caption-words.ts`로 재현합니다.
- 새 자막은 한글·이모지 번들 글꼴과 공통 Canvas 래스터를 사용합니다. 30·60·120fps, 분할, 기존 ASS와 겹침 순서, 구간 출력·취소, 캐시 한도를 검사했습니다. 실제 120fps 73프레임의 CPU 미리보기는 동일 색 변환 후 출력과 같고 WebGL 자막 영역 평균 오차는 최대 0.631/255입니다.
- 단어 시간 편집, 24개 사용자 스타일, 일괄 적용, 3개 기본 스타일, 개별 등장·퇴장 효과를 추가했습니다. 작은 창에서도 목록과 시간·스타일 버튼에 접근할 수 있습니다.
- 4K30·2초 합성 자막 출력 1.860초, 빈 화면 1.275초를 측정했습니다. CPU 자막/영상 합성과 NVENC 인코딩이며 일반 프로젝트의 속도 수치는 아닙니다. 60프레임 중 47개 상태를 재사용합니다.
- 테스트용 Electron 프로세스의 닫힌 표준 출력에 로그를 쓰면서 발생한 EPIPE를 재현하고 소유 로그·부모 감시·종료 정리를 적용했습니다. 로그/부모 연결 종료 회귀에서 창 0개를 확인했습니다.
- 기본 검사 182개 통과·선택형 5개 제외, 통합 검사와 실제 소스 앱·배포 EXE 각각 137개 검사를 통과했습니다. 배포 EXE의 GPU 전환 출력 7개, 자막 출력 5개, 포터블 8개, 설치 payload 무결성 162개도 통과했습니다. 포터블 첫 화면은 이 환경에서 13.77초였습니다. 실제 설치와 다른 PC 호환성은 확인하지 않았습니다.
- 연속 수동 저장에서 이전 요청의 비동기 경로 확인이 늦어져 최신 파일을 덮던 문제를 발견했습니다. 요청 전체를 순서대로 처리하고 종료 시 기다리도록 수정했습니다. 실제 IPC에서 이전 요청을 500ms 늦춰도 최신 내용이 남고, 저장 도중 종료해도 대기 중인 최신 저장을 끝내는 것을 검증했습니다.
- 숨김 UI 검사는 Windows/Electron45의 1fps 제한을 피하기 위해 검사 실행기에만 `--disable-frame-rate-limit`을 전달합니다. 일반 앱과 별도 성능 측정에는 적용하지 않습니다. 원인은 실제 4초간 4회 대 374회 프레임 콜백으로 확인했습니다.
- 배포 EXE의 숨김 창을 크기 조절한 뒤 CDP 화면 캡처가 멈추는 검사 도구 문제는 Electron의 `capturePage`로 캡처하도록 수정했습니다. 창이 계속 숨겨져 있고 이미지가 비어 있지 않은지 검사하며 실제 편집 화면도 확인했습니다.
- 실제 ASAR의 비공개 자막 창이 번들 폰트 2개를 오프라인으로 읽는지, 120fps CPU/NVENC 출력 73프레임이 원시 기준 영상과 맞는지, 출력 도중 취소했을 때 파일·자식 프로세스·자막 창이 남지 않는지 확인했습니다. 인코딩된 자막 영역 평균 오차의 최대값은 CPU 3.168/255, NVENC 0.970/255입니다. 별도 무손실 CPU 기준 검사는 바이트가 같습니다.

## 1.5 색 보정 작업

- 이전 목표 턴은 1.4 실제 배포·무결성 검증을 완료한 진전입니다. 현재 작업은 부족한 색 보정 기능을 확장하며, 1.4 배포 파일을 덮어쓰지 않습니다.
- RGB 전체와 빨강·초록·파랑 개별 곡선, 2–16개 제어점, 부드러운 보간, 직접 드래그·숫자·키보드 조정, 비교용 사용/해제, 초기화를 구현했습니다. GPU와 출력은 동일한 4096개 곡선 샘플을 사용합니다.
- 2–65 크기의 3D `.cube` LUT, `DOMAIN_MIN/MAX` 또는 `LUT_3D_INPUT_RANGE`, 강도 조절을 지원합니다. 혼합 1D+3D·단독 1D LUT와 알 수 없는 헤더는 조용히 무시하지 않고 가져오기를 거부합니다. 파일 한도 16MiB, 프로젝트는 최대 32개 LUT·총 200만 float 값입니다. SDR 범위이며 HDR·로그 색 공간 자동 변환을 뜻하지 않습니다.
- LUT는 형식 5 프로젝트에 little-endian float32/base64로 저장합니다. 외부 LUT 경로에 의존하지 않으며 동일 파일을 중복 등록하지 않습니다. 클립 복사본은 LUT를 함께 유지하고, 사용하지 않는 LUT 정리 이후 붙여넣어도 해당 LUT를 복원합니다. 분할·저장·다시 열기에도 곡선을 유지합니다.
- GPU 미리보기는 3D 텍스처의 사면체 보간, CPU 대체 미리보기는 같은 계산을 사용합니다. 내보내기는 16비트 중간 영상과 FFmpeg `lut1d/lut3d`, 곡선 → LUT → 강도 혼합 순서입니다. 기존 기본 조정·프리셋 다음, 마스크·변환 전에 적용합니다. 보정이 있는 클립은 효과를 생략하는 단순 출력 경로를 사용하지 않습니다.
- 실제 FFmpeg 출력 8조건과 CPU 기준 비교에서 RGB 평균 차이는 최대 0.302/255, 최대 차이 2/255입니다. RTX 4080 SUPER의 실제 WebGL2/CPU 미리보기 16회 비교에서도 출력과 최대 2/255 이내였습니다. 보정 해제·LUT 강도 0은 원본 픽셀과 같고, 단일 이미지 15프레임의 실제 타임라인 출력은 같은 색 변환의 기준 영상과 바이트가 같습니다. 근거: `.test-artifacts/color-render/results.json`, `.test-artifacts/color-pixels/results.json`.
- 65³ LUT 자동 저장 요청 12회에서 동기 contextBridge 복사·IPC 전달은 숫자 배열일 때 평균 31.42ms/최대 37.5ms, packed float32에서는 평균 1.63ms/최대 5.2ms였습니다. 해당 프로젝트 JSON은 13,361,258 → 4,395,590바이트입니다. 비동기 저장·전체 편집 속도 수치가 아닌 이 PC의 특정 전달 비용입니다. 디코딩 캐시 48MiB, GPU LUT 텍스처 32MiB, 곡선 텍스처 32개로 제한합니다.
- 실제 UI 검사에서 가져오기·중복 방지·강도 Home 키 실행 취소·비교 해제·곡선 드래그 한 번의 실행 취소·개별 채널·트랙 잠금·다중 선택·복사/정리/붙여넣기·작은 창·원본 LUT 이동 후 재열기를 확인했습니다. 실제 내보내기 창의 NVENC 영상 15프레임도 기준과 비교했습니다. 스코프 추가 후 전체 기본 검사는 200개 통과·선택형 5개 제외, 전체 소스 UI는 162개 통과입니다.
- 재현: `npm run test:color`는 빌드·색 보정 단위·FFmpeg·GPU/CPU 픽셀·실제 UI 검사를 실행합니다. `npm run test:scopes`는 분석 계산과 실제 화면의 Worker·표시·해제 검사를 실행합니다. `npm run test:e2e`에도 두 UI 검사를 포함합니다. 실제 EXE 검사는 `SLU_TEST_EXE`를 `release/win-unpacked/SLU Studio.exe`로 지정해 실행했습니다. 형식 5를 이전 EXE에서 열 수 없습니다. HSL·HDR과 다른 미완성 영역은 계속 남습니다.
- 성능 후속 작업: 이번 4K30·2초 자막 표본은 빈 화면 2.850초, 자막 5.662초였고 포터블 첫 화면은 40.51초였습니다. 이전 측정과 부하·캐시 조건이 같다고 입증되지 않았으므로 원인이나 개선율을 단정하지 않습니다. 시작 시 압축 해제와 앱 초기화를 나눠 측정하고 긴 색 보정 출력의 처리량도 확인해야 합니다.

색 보정 출력 참고: [FFmpeg LUT 필터 문서](https://ffmpeg.org/ffmpeg-filters.html#lut3d), [FFmpeg LUT 구현](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/vf_lut3d.c). 프로젝트 안의 계산과 테스트는 실제 번들 FFmpeg로 별도 확인합니다.
